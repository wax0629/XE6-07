# 提案：建立成品、数字模型与会员权益的多层商业化服务

## 动机 / 用户故事

用户完成一次 3D 创作后，可能希望获得打印成品、下载模型自行打印，或者持续使用生成、修改和检查能力。创作者、学校和打印服务方也可能希望在同一平台上提供内容或组织多人使用。

如果商业化只依赖一种商品，平台会把不同用户强制放进同一付费方式：低频用户不愿订阅，有打印机的用户不需要成品，高频用户又会反复按次购买。因此需要先确定一套可逐层验证的商业服务轮廓。

本提案的共同需求是：围绕同一个模型资产，允许用户按需要购买实物、数字授权或持续服务，并在后续为创作者和机构提供参与方式。

## 目标用户

- 希望直接获得 3D 打印成品的普通用户。
- 拥有打印机、只需要可打印模型文件的用户。
- 持续生成、修改和管理模型的高频用户。
- 希望发布原创模型并获得收入的创作者。
- 需要多人协作、共享额度和管理打印任务的学校、创客空间或工作室。

## 现有做法及不足

市场中的 3D 生成平台通常销售订阅或生成额度，模型社区主要销售数字模型或商业授权，打印服务则按实物订单收费。这些模式分别解决单个环节，但用户仍需要自己判断模型是否可打印、如何切片以及由谁完成打印。

当前项目已经规划生成、资产、可打印性检查、切片和打印链路，但尚未定义这些能力分别能够形成什么商品，以及单次购买、持续订阅和平台分成之间如何共存。

## 本期范围

本期确定：

- 商业化围绕同一模型资产形成多层服务，而不是只依赖一种收费方式。
- 低频用户可以单次购买，不强制订阅。
- 实体成品、数字模型、按量服务和持续服务是四类不同的可售价值。
- 计算成本随使用量增长的服务可以使用付费额度计量。
- 奖励积分与付费额度分开，避免把营销奖励当成现金或创作者收入。
- 创作者可以通过数字模型授权或实体销售获得分成。
- 机构可以购买多人共享和管理能力。
- 各层商业模式独立验证，前一层成立后再扩大后一层。

本期明确不做：

- 不确定具体商品价格、会员档位、额度消耗标准和平台分成比例。
- 不设计支付、钱包、结算或税务的具体实现。
- 不承诺同时上线所有商业模式。
- 不在本提案中定义具体打印商品的尺寸、材料和履约规则。
- 不自动赋予用户生成内容的商业授权，具体权利范围另行讨论。

## 关键决策与依据

### 备选方案

1. **只销售打印成品**
   - 优点：用户购买结果，价值直接。
   - 缺点：履约较重，无法覆盖已有打印机或只需要文件的用户。
2. **只销售生成订阅或额度**
   - 优点：数字化交付，容易扩展。
   - 缺点：与完整打印闭环的产品定位脱节，也难以服务低频用户。
3. **建立多层商业服务**
   - 优点：同一模型可以产生实体交付、数字授权、按量服务和持续服务等不同价值，能够覆盖不同频率和能力的用户。
   - 缺点：需要明确各层边界，并按阶段逐步验证。

### 选择与理由

选择方案 3，但不要求一次完成全部能力。

平台的核心不是把所有用户变成订阅用户，而是让用户根据目标选择合适的付费出口：需要实物时购买成品，需要文件时购买数字模型，高频使用时再选择会员或额度。

## 商业服务轮廓

### 第一层：实体成品

面向没有打印机或不熟悉打印流程的用户。平台提供模型确认、可打印性检查、切片、打印和交付，收入来自单次实体订单。

该层只定义“出售完整交付结果”的商业方向，具体商品通过独立试点 Proposal 验证。[PR #152](https://github.com/1024XEngineer/XE6-07/pull/152) 是桌面摆件方向的首个试点，不构成本提案对商品范围和价格的承诺。

### 第二层：数字模型

面向拥有打印机或只需要文件的用户。可售内容可以是原始模型、经过可打印性检查的模型包、修复版本或包含打印建议的文件组合。

数字模型必须附带明确授权，例如个人使用、允许修改或允许销售实体打印品。购买文件不自动等于获得版权或无限制商业权利。

### 第三层：会员订阅

面向持续创作和管理模型的高频用户。会员销售的是一组周期性权益，例如生成和修改额度、任务优先级、私有资产空间、版本历史、模型权益或打印优惠。

基础单次购买能力不应被会员完全取代，避免低频用户必须订阅才能完成一次创作。

### 第四层：付费额度与奖励积分

付费额度用于计量生成、重新生成、模型修复、高精度处理或其他随使用量增长的计算服务。额度可以单独购买，也可以作为会员权益发放。

奖励积分用于鼓励发布模型、补充打印反馈或参与社区，可以兑换优惠或有限权益。奖励积分不直接提现，也不替代创作者应得的真实收入。

### 第五层：创作者服务

创作者可以发布原创模型，并选择免费分享、付费下载、会员专属或实体销售授权。平台可以提供交易、授权记录、文件交付和代打印服务，并从交易或履约中获得服务分成。

创作者的可结算收入必须与用户积分、平台额度分开记录。

### 第六层：机构服务

面向学校、创客空间和打印工作室提供多人账户、共享资产、共享额度、打印任务管理、设备与耗材管理以及使用统计。后续可以根据需求选择团队订阅、用量计费、API 或私有化服务。

## 基本概念与信息结构

### 可售价值

- **实体交付**：用户购买经过确认和制作的实物结果。
- **数字授权**：用户获得在约定范围内下载、使用或商业使用模型的权利。
- **按量权益**：用户购买生成、修复、检查等计量服务，付费额度是这类权益的计量载体。
- **持续权益**：用户在一定周期内获得会员服务；会员可以附赠按量额度，但两类权益保持独立。

### 账户权益

- **付费额度**：购买或随会员获得，用于消费计量服务。
- **奖励积分**：通过平台行为获得，用于兑换优惠，不等同现金。
- **创作者收入**：来自真实交易并按规则结算，与前两者分离。

### 商业关系

同一模型可以同时关联数字授权、实体订单和创作者分成，但每次交易必须明确用户购买的对象、权利范围和交付责任。

## 推荐演进顺序

```text
实体成品试点
→ 数字模型单次购买
→ 付费额度
→ 会员订阅
→ 创作者交易与分成
→ 机构服务
```

该顺序用于降低同时建设多套商业系统的风险，不表示所有商业模式都必须上线。每一层都需要独立 Proposal 和验证结果才能进入实现。

## 验收标准

### 例子 1：低频用户购买实体成品

- 现状：用户可能只需要一次服务，却被要求购买长期订阅。
- 提议后的行为：用户可以不订阅会员，直接购买一次实体交付。
- 验收：成品订单能够独立成立，价格和交付责任不依赖会员身份。

### 例子 2：已有打印机的用户购买模型

- 现状：用户只需要模型文件，但只能购买平台代打印的实物。
- 提议后的行为：用户可以购买带有明确授权和打印说明的数字模型。
- 验收：交易明确交付文件、允许用途和限制，不把文件购买描述为版权转让。

### 例子 3：高频用户选择会员或按量服务

- 现状：高频用户需要重复购买每次生成或修改服务。
- 提议后的行为：用户可以按周期购买会员持续权益，也可以单独购买按量额度，并保留其他单次购买入口。
- 验收：会员持续权益、按量额度和其他单次付费范围能够被清楚区分；额度是否过期可以另行决策，不影响其归类，未订阅用户不会失去基本购买能力。

### 例子 4：创作者获得收入

- 现状：模型发布只形成内容，没有清晰的商业回报路径。
- 提议后的行为：创作者可以选择付费下载或实体销售授权，并按后续规则获得分成。
- 验收：真实交易收入与奖励积分、平台额度分开记录，授权范围能够随交易追溯。

### 例子 5：机构统一使用

- 现状：学校或工作室只能让成员分别购买个人服务。
- 提议后的行为：机构可以统一管理成员、共享资产和使用额度。
- 验收：机构服务被识别为独立商业层，不通过共享个人账号模拟多人使用。

### 例子 6：新商业功能归类

- 现状：新收费想法可能直接进入实现，造成商品、权益和结算概念混杂。
- 提议后的行为：每个新商业功能先说明出售的价值、目标用户、收费方式及所属层级。
- 验收：无法明确归入实体交付、数字授权、按量权益、持续权益、创作者服务或机构服务的功能，不直接进入实现。

## 待讨论

- 平台长期收入应更偏向实体履约，还是数字模型和持续服务。
- 用户生成模型的所有权、下载权和商业使用权如何划分。
- 会员额度是否累计，以及付费额度是否设置有效期。
- 奖励积分可以兑换哪些权益，如何避免形成现金承诺。
- 创作者定价、平台分成和退款责任由谁承担。
- 机构服务是否应在消费者商业模式稳定后再进入验证。
