# 提案：GLB 模型预览与基础信息展示

## 动机 / 用户故事

用户生成或上传模型后，需要在自己的处理页面直观看到 GLB，确认文件能否加载、模型外观是否符合预期，以及大致复杂度如何，再决定是否发起可打印审计。

共同需求是：提供稳定、可交互、失败时不拖垮整页的模型预览，并把用户明确引导到后续审计流程。

## 目标用户

- 生成或上传 GLB 模型并准备继续处理的普通用户
- 需要查看当前模型版本基础信息的创作者

## 现有做法及不足

缺少统一预览时，用户无法在平台内确认 GLB 是否可用，只能直接进入审计或下载到外部工具查看。文件缺失、格式错误或加载失败也可能只表现为页面空白，阻断后续操作。

## 本期范围

本期做：

- 加载用户当前模型版本的 GLB 预览。
- 支持旋转、平移、缩放和重置视角。
- 展示顶点数、三角面数等基础信息。
- 区分加载中、加载成功、文件缺失、格式不支持和加载失败。
- 预览失败时显示原因和重试入口，页面其他信息仍可使用。
- 提供进入可打印审计的明确操作入口。

本期明确不做：

- 不执行水密性、流形和壁厚等可打印审计。
- 不高亮网格问题或自动修复模型。
- 不做公共模型库、下载、收藏或发布审核。
- 不固定前端渲染库、存储路径、数据库字段或 API 设计。

## 关键决策与依据

### 备选方案

1. 把预览、审计和修复做成一个不可分割页面
   - 优点：入口集中。
   - 缺点：预览失败可能阻断其他流程，也难以独立验证基础体验。
2. 先提供独立预览能力，再由明确入口进入审计
   - 优点：职责清晰，用户可以先确认文件和外观；失败状态更容易隔离。
   - 缺点：用户需要执行一次进入审计的操作。

### 本期选择

选择方案 2。

原因：预览是审计前的基础确认能力，不应把审计规则或修复实现提前耦合进查看器；单个预览失败也不能让处理页整体不可用。

## 基本概念与信息结构

### 当前模型版本

预览必须绑定用户当前选择的模型版本，不自动切换到其他版本。

### 预览状态

- 加载中
- 加载成功
- 文件缺失
- 格式不支持
- 加载失败

### 基础模型信息

- 顶点数
- 三角面数
- 其他基础信息可后续扩展，但不包含可打印审计结论。

## 原型 / 演示

处理页包含 GLB 查看区域、基础信息、重试入口和“开始可打印审计”操作。错误状态替换查看区域，但不覆盖页面其他内容。

## 验收标准

### 例子 1：预览有效 GLB

- 现状：用户无法在平台内确认当前模型外观。
- 提议后的行为：系统加载 GLB 并提供基础交互。
- 验收：用户能够旋转、平移、缩放和重置视角；所有操作作用于当前模型版本，查看器保持可用。

### 例子 2：展示基础信息

- 现状：用户无法判断模型大致复杂度。
- 提议后的行为：系统读取并展示基础网格信息。
- 验收：页面显示与实际 GLB 一致的顶点数和三角面数，不把这些信息误标为可打印审计结果。

### 例子 3：区分加载状态

- 现状：加载中、文件缺失、格式错误和通用失败可能都表现为空白。
- 提议后的行为：系统使用不同状态和可理解说明。
- 验收：每种状态可独立触发和验证；失败状态提供重试，成功前不显示虚假的模型或基础信息。

### 例子 4：预览失败隔离

- 现状：单个文件加载失败可能导致整个处理页不可用。
- 提议后的行为：失败只影响查看区域。
- 验收：模型名称、版本信息和其他页面操作仍可访问；重试不会重复创建模型版本或改变文件。

### 例子 5：进入可打印审计

- 现状：用户预览后不知道下一步如何验证打印兼容性。
- 提议后的行为：页面提供明确的审计入口。
- 验收：点击后把当前模型版本传入可打印审计流程，不在预览模块内部执行或伪造审计结果。

### 例子 6：不支持或损坏的文件

- 现状：非 GLB、损坏或不可解析文件可能让页面进入不确定状态。
- 提议后的行为：系统阻止预览并展示具体原因。
- 验收：不显示空白成功状态，不进入审计，用户可以返回或重试加载有效文件。
