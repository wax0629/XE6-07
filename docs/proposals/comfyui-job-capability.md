# 提案：ComfyUI 算法任务能力

## 动机 / 用户故事

Hunyuan3D 多视图生成是长耗时 GPU 任务。算法服务需要把一次生成执行抽象为可持久化、可查询、可取消和可追溯的 `AlgorithmJob`，并向后端返回稳定状态，同时隐藏 ComfyUI 节点、队列和文件路径。

## 目标用户

- 调用 3D 生成能力的后端服务
- 维护 ComfyUI、任务队列、Worker 和 GPU 资源的算法工程师

后端服务是唯一业务调用方。前端、外部 Agent、SDK 和终端用户不直接调用算法任务接口。

## 本期范围

算法服务负责：

- 创建 `AlgorithmJob` 并返回稳定唯一标识。
- 使用调用方幂等键避免重复生成。
- 校验输入与算法参数后再进入队列。
- 管理队列、Worker、GPU 并发和算法任务优先级。
- 执行 ComfyUI 工作流并转换内部执行状态。
- 提供任务状态、阶段、进度、取消、超时和结构化失败。
- 持久化任务及参数快照，支持服务重启后的恢复或确定终态。
- 关联成功任务的 GLB、预览图和必要元数据。
- 记录工作流版本、参数、输入哈希、输出哈希和运行日志。

后端服务负责：

- 用户身份、权限、产品状态和业务任务生命周期。
- 保存 `businessTaskId -> algorithmJobId` 映射。
- 将算法状态转换为面向用户的业务状态和提示。
- 决定用户能否提交、取消或重新生成。

## 明确不做

- 不向前端、外部 Agent 或第三方系统直接开放算法任务接口。
- 不向后端暴露 ComfyUI prompt ID、节点 ID、原始事件或服务器路径。
- 算法任务成功不代表模型已通过可打印性检查、发布审核或打印门禁。
- 算法服务不维护用户、项目、收藏、社区或打印业务状态。
- 已提交任务的参数不可原地修改；修改参数必须创建新任务。

## 基本概念

```text
AlgorithmJob {
  id
  idempotencyKey
  inputRefs
  resolvedParameters
  workflowVersion
  status
  stage
  progress
  outputs
  error
  createdAt
  startedAt
  finishedAt
}
```

稳定状态包括：`queued`、`running`、`succeeded`、`failed`、`cancelled` 和 `timed_out`。ComfyUI 内部事件只用于算法服务内部诊断。

## 验收标准

### 例子 1：后端提交与幂等

- 后端以同一幂等键重复提交相同请求时，只创建一个算法任务并返回同一 `algorithmJobId`。
- 同一幂等键对应不同输入时，请求被拒绝并返回稳定错误码。

### 例子 2：状态隔离

- 后端只能看到稳定状态、阶段和进度，不包含 ComfyUI 节点、prompt ID、内部队列 ID 或服务器路径。
- 前端和外部 Agent 不能直接访问算法任务接口。

### 例子 3：取消与终态

- `queued` 和允许取消的 `running` 任务可以请求取消。
- 重复取消保持幂等；成功、失败、取消和超时都是不可逆终态。

### 例子 4：失败与恢复

- Worker 中断或服务重启后，每个已接受任务都能恢复执行或进入可解释终态。
- 失败响应包含稳定错误码、可重试性和算法侧诊断标识，不泄露内部堆栈。

### 例子 5：产物完整

- 只有约定 GLB 及其哈希、工作流版本和参数快照全部关联后，任务才能进入 `succeeded`。
- 可打印性检查、切片和打印仍由后端后续流程决定。
