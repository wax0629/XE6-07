# 提案：收藏公开模型与“我的收藏”

## 动机 / 用户故事

登录用户浏览公共模型时，希望保存喜欢的模型，以便之后在个人列表中重新找到，而不是依赖浏览器书签或再次搜索。

共同需求是：用户可以收藏和取消收藏公开模型，并在“我的收藏”中看到自己仍可访问的收藏记录。

## 目标用户

- 浏览公共模型并希望稍后重新访问的登录用户
- 维护公共模型状态和可见性的社区服务

## 现有做法及不足

没有平台内收藏关系时，用户只能依赖外部书签或重复搜索。模型公开状态发生变化后，也缺少统一规则决定收藏记录、计数和私有内容如何处理。

## 前置能力

- 公共模型详情页能够展示当前审核通过的公开版本。
- 模型公开、非公开和已下架状态能够被稳定判断。

## 本期范围

本期做：

- 在公共模型详情页提供收藏和取消收藏。
- 收藏成功后把模型加入当前用户的“我的收藏”。
- “我的收藏”按收藏时间倒序展示公开模型卡片。
- 同一用户对同一模型最多存在一条收藏关系。
- 重复点击或网络重试不重复创建关系或增加计数。
- 取消收藏后移除关系并减少收藏数，计数不得小于零。
- 未登录用户点击收藏时引导登录，不创建记录。
- 下架或重新变为非公开的模型不能新增收藏。
- 已有收藏关系保留为历史，但不得暴露下架或私有内容。
- 区分空列表、加载失败和操作失败状态。

本期明确不做：

- 不做点赞、评分、评论和关注。
- 不做收藏夹分组和批量管理。
- 不做收藏通知、推荐和排行榜。
- 不做离线下载。
- 不做举报和 Fork。

## 关键决策与依据

### 备选方案

1. 只在客户端保存收藏状态
   - 优点：实现简单。
   - 缺点：不能跨设备同步，也无法可靠维护去重和收藏数。
2. 为用户和模型保存唯一收藏关系，服务端维护幂等和计数
   - 优点：可以跨设备查询，并能处理重试、取消和权限变化。
   - 缺点：需要维护关系、计数一致性和模型状态联动。
3. 模型下架或转私有时删除全部收藏关系
   - 优点：列表中不再出现不可用模型。
   - 缺点：丢失用户历史，重新公开后无法恢复原关系。

### 本期选择

选择服务端唯一收藏关系；模型不可用时保留关系但隐藏内容和操作。

原因：收藏需要跨设备、幂等和用户隔离；保留关系可以维持历史，同时通过公开状态门禁避免私有内容泄露。

## 基本概念与信息结构

### 收藏关系

- 关联一个用户和一个模型。
- 同一用户与模型组合唯一。
- 记录收藏时间，用于列表倒序。

### 收藏计数

- 收藏成功增加一次。
- 取消收藏减少一次，但不得小于零。
- 重复请求不得重复改变计数。

## 原型 / 演示

公共模型详情页提供收藏状态按钮。“我的收藏”使用公共模型卡片，包含加载中、空列表、加载失败和模型不可用状态。

## 验收标准

### 例子 1：收藏和取消公开模型

- 现状：用户无法在平台内保存喜欢的公开模型。
- 提议后的行为：登录用户可以收藏公开模型，并再次操作取消收藏。
- 验收：收藏后按钮立即更新、关系持久化、计数增加一次、模型进入“我的收藏”；取消后关系移除、计数减少一次、模型从列表移除。

### 例子 2：重复请求与网络重试

- 现状：重复点击或重试可能创建多条关系并重复计数。
- 提议后的行为：收藏和取消操作保持幂等。
- 验收：同一用户重复收藏只存在一条关系且计数只增加一次；重复取消不会让计数小于零。

### 例子 3：未登录用户

- 现状：未登录用户无法建立稳定归属的收藏关系。
- 提议后的行为：系统引导登录，不创建收藏。
- 验收：登录完成前数据库无收藏记录，页面不显示虚假的成功状态。

### 例子 4：我的收藏与用户隔离

- 现状：用户可能看不到历史收藏，或错误看到其他用户的记录。
- 提议后的行为：列表只查询当前用户关系，并按收藏时间倒序。
- 验收：用户只看到自己的收藏；新收藏排在旧收藏前；空列表和加载失败使用不同状态。

### 例子 5：模型下架或转为非公开

- 现状：收藏列表可能继续暴露已下架或私有模型的详情和文件。
- 提议后的行为：禁止新增收藏，已有关系保留为不可用历史项。
- 验收：列表仅显示“已下架/不可用”，不提供详情、预览或下载，也不暴露未经审核的新版本；模型仍公开时收藏始终指向当前公开内容。

### 例子 6：操作失败

- 现状：请求失败后按钮可能停留在错误状态。
- 提议后的行为：系统恢复操作前状态并提示重试。
- 验收：失败不改变持久化关系和收藏数，页面明确区分操作失败与列表加载失败。
