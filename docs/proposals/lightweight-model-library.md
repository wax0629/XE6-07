# 提案：轻量模型库：发布、审核与下载

## 动机 / 用户故事

用户生成或上传 3D 模型后，目前只能自行下载保存，优秀模型无法被其他用户发现和复用。

典型场景包括：

1. 用户生成一个可打印摆件，希望保存后下次继续使用。
2. 用户愿意分享模型，但不希望通过网盘或聊天工具手动传递文件。
3. 其他用户希望寻找可下载模型，并在下载前了解模型的基本信息和可用文件格式。

共同需求：平台需要建立一个最基础的模型沉淀与分享闭环，让个人结果能够成为可公开、可发现、可下载的平台资产。

## 目标用户

- 生成或上传模型的普通用户
- 希望浏览、收藏和下载公开模型的普通用户
- 负责审核公开模型的运营或管理人员

## 现有做法及不足

当前流程为：

```text
生成模型
  -> 用户自行下载
  -> 本地保存或手动分享
```

这会导致模型停留在个人文件中，其他用户无法浏览、收藏或下载；平台也无法控制哪些模型可以公开。用户每次分享模型仍需手动传递文件。

## 本期范围

本期做：

- 让用户生成或上传的模型自动进入“我的模型”，并展示封面、名称、来源、状态和创建时间。
- 在“我的模型”中提供查看、下载、提交发布和删除操作。
- 支持用户以标题、描述、分类、标签和授权方式提交发布；仅当封面、预览模型、STL 或 3MF 文件及必填字段齐全时可提交审核。
- 提交发布后调用独立审核能力；本提案只消费其当前公开状态和已审核公开版本，不重复定义审核操作、并发或历史状态机。
- 提供仅展示已审核通过模型的公共模型库，支持浏览、分类筛选、关键词搜索和进入详情页。
- 提供模型详情页，展示 3D 预览、模型信息、授权方式、收藏数和下载数；支持收藏、下载 STL、下载 3MF 和举报。

本期明确不做：

- 评论、点赞、关注、私信和动态流
- Remix 或二次创作
- 打印反馈、成品图、成功打印次数
- 打印参数分享、多材料和多打印机配置
- 付费或会员模型、创作者分成
- 排行榜、积分和作者等级
- 复杂推荐算法
- G-code 下载
- 复杂版权识别；仅提供基础审核和举报入口
- 审核通过、驳回、下架、版本锁定、并发处理和操作历史的具体规则；这些由独立审核能力负责

## 关键决策与依据

### 备选方案

1. 完整社区：在模型发布之外，同时提供社交、创作激励、推荐、打印反馈和二次创作。
   - 优点：社区互动和创作者能力完整。
   - 缺点：范围过大，无法先验证用户是否愿意发布、浏览和下载模型。
2. 无审核的公开模型库：用户提交后直接公开。
   - 优点：发布路径短。
   - 缺点：公开区域缺少对低质量或违规模型的基础控制。
3. 基础模型沉淀与分享闭环：我的模型、提交发布、审核、公共模型库、详情、收藏与下载。
   - 优点：覆盖模型从个人结果到公开资产的最小路径，并为后续能力保留基础。
   - 缺点：本期不覆盖社交、打印反馈、二次创作和商业化能力。

### 本期选择

选择方案 3，并要求公开模型先经过审核。

原因：该方案先验证用户是否愿意发布、浏览和下载模型，且让平台能够对公开内容进行基础控制。后续社交、打印反馈、Remix、打印配置和商业化能力都可以建立在该闭环之上。

本期仅支持 STL 和 3MF 下载。G-code 与打印机、材料、温度、喷嘴和坐标设置强相关，直接复用风险高，不作为基础模型库的一期能力。

发布字段保持最少：不要求用户填写打印材料、支撑、层高和填充率等专业参数，以降低发布门槛，优先验证分享闭环。

## 基本概念与信息结构

### 模型

平台中的基础内容对象，包含：

- `title`：模型标题
- `description`：模型描述
- `cover`：封面
- `previewFile`：可预览模型文件
- `printFiles`：STL 和/或 3MF 文件
- `author`：作者
- `category`：分类
- `tags`：标签
- `license`：授权方式
- `status`：私有、审核中、已公开、审核未通过或已下架

### 模型状态

- 私有：仅作者可见。
- 审核中：已提交，等待审核。
- 已公开：审核通过，所有用户可见。
- 审核未通过：未进入公共模型库；作者可见驳回原因。
- 已下架：曾公开，但已被管理员移除。

上述状态由独立审核能力提供。本提案只根据状态决定“我的模型”、公共列表和详情中的可见操作，不直接执行通过、驳回或下架。

### 收藏

用户与公开模型之间的保存关系。本期用于让用户后续快速找到模型，并在模型卡片展示收藏数。

### 举报

用户对已公开模型发起的反馈记录，包含被举报模型、举报人和必填的举报原因。提交举报不自动改变模型的公开状态；管理员可查看举报并决定是否下架模型。

## 验收标准

### 例子 1：生成或上传的模型进入我的模型

- 现状：用户完成生成或上传后，只能自行下载并保存模型。
- 提议后的行为：生成或上传完成的模型自动进入该用户的“我的模型”，状态为私有。
- 验收：以一条来源为 AI 生成和一条来源为用户上传的模型记录完成流程；两条记录均出现在当前用户的“我的模型”中，分别展示封面、名称、来源、私有状态和创建时间，并可从该列表查看、下载或删除。

### 例子 2：满足条件的模型可提交审核

- 现状：用户没有统一的公开发布入口，模型只能手动分享。
- 提议后的行为：用户从“我的模型”提交发布，填写标题、描述、分类、标签和授权方式；校验通过后进入审核中状态。
- 验收：对一条同时具有封面、可预览模型、STL 或 3MF 文件且必填字段完整的私有模型，提交发布后，该模型状态变为审核中；其公开展示路径尚不可从公共模型库检索或浏览到。

### 例子 3：缺少必要信息的模型不得提交

- 现状：缺少可下载文件或必填信息时，用户可能错误地认为模型已被提交。
- 提议后的行为：提交前校验封面、预览模型、STL 或 3MF 文件，以及标题、描述、分类和授权方式；缺失时阻止提交并提示缺少项。
- 验收：分别对缺少封面、可预览模型、STL 或 3MF 文件、标题、描述、分类、授权方式的模型发起提交；每次均保留原状态，不创建审核中记录，并向用户明确指出缺失内容。

### 例子 4：消费审核结果决定公开可见性

- 现状：平台无法控制哪些模型可在公共区域出现。
- 提议后的行为：模型库消费审核能力给出的 `publishedRevision` 与公开状态；只有当前已公开且未下架的审核版本进入公共模型库。
- 验收：审核能力返回已公开状态和锁定的 `publishedRevision` 后，公共列表、搜索与详情均只展示该版本；返回审核未通过时仅作者在“我的模型”看到原因；返回已下架时公共列表、详情和下载均不可用。本提案不另行生成审核操作或状态历史。

### 例子 5：公开模型可收藏并下载允许的文件格式

- 现状：其他用户无法发现、保存或获取公开模型文件。
- 提议后的行为：用户在公开模型详情页可收藏模型，并下载 STL 或 3MF 文件。
- 验收：用户打开一条已公开模型的详情页，页面展示 3D 预览、标题、作者、描述、分类、标签、授权方式、发布时间、收藏数和下载数；点击收藏后，该模型进入该用户的收藏列表且卡片收藏数可展示；点击下载 STL 或下载 3MF 后，获得相应文件。

### 例子 6：举报公开模型

- 现状：用户发现疑似不合适的公开模型时，没有向平台反馈的入口。
- 提议后的行为：仅在已公开模型的详情页提供举报。用户填写举报原因并提交后，系统记录被举报模型、举报人和原因，反馈“举报已提交”；提交举报不自动改变模型的公开状态。管理员可查看举报并决定是否下架模型。
- 验收：用户对一条已公开模型提交包含原因的举报后，收到提交成功反馈；管理员可看到该举报关联的模型、举报人和原因；模型在管理员执行下架前仍保持已公开。私有、审核中、审核未通过和已下架模型不显示举报入口。

### 例子 7：不支持的文件与下载类型不得进入公开流程

- 现状：用户可能尝试以无效资产提交，或希望取得与设备配置强相关的 G-code。
- 提议后的行为：未满足文件校验的模型不能进入审核；公开详情页不提供 G-code 下载。
- 验收：对没有 STL 或 3MF 的模型提交发布时，系统阻止提交并明确提示缺少可下载文件；打开任意公开模型详情页时，页面只提供 STL 和/或 3MF 下载入口，不出现 G-code 下载入口。
