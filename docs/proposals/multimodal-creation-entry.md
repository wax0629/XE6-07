# 提案：多模态创作入口

## 动机 / 用户故事

用户可能从一句想法、一张参考图、图文组合或一个已有模型开始创作。

共同需求是：系统应识别用户给出的输入类型，并进入正确的后续流程，而不是要求用户先理解平台能力边界和内部生成链路。

## 目标用户

- 想快速生成 3D 打印模型的新手用户
- 有参考图片但不会建模的创作者
- 已有 GLB/STL/OBJ 模型、希望检查或打印的用户

## 现有做法及不足

如果入口被拆成“文字生成”“图片生成”“上传模型”等多个独立入口，用户需要在创作前先判断自己应该使用哪个流程。

这个判断成本对新手不友好，也会把平台的能力边界暴露给用户。用户真正关心的是“我手里有这些素材，下一步怎么变成可打印模型”，而不是先理解概念图生成、图生 3D、模型审计等内部路径。

## 本期范围

本期做：

- 一个创作入口支持四类输入：
  - 纯文本
  - 图片
  - 文本 + 图片
  - 已有 3D 模型
- 输入后系统自动判断主流程：
  - 纯文本：进入概念图生成
  - 图片：进入图生 3D
  - 文本 + 图片：图片作为主参考，文本作为约束
  - 3D 模型：进入模型审计
- 展示用户当前输入被识别为何种类型，并允许用户确认后继续。

本期明确不做：

- 不支持视频、音频、扫描点云输入
- 不做专业 CAD 参数化建模
- 不支持一次上传多个模型后自动合并
- 不做复杂的图层、部件级编辑

## 关键决策与依据

采用“单入口 + 自动分流 + 用户确认”的方案。

### 备选方案

1. 多入口：分别提供“文字生成”“图片生成”“上传模型”
   - 优点：实现清楚，流程拆分直观。
   - 缺点：用户必须先理解平台流程，容易在入口选择上卡住。
2. 单入口但完全自动分流
   - 优点：路径最短，用户操作最少。
   - 缺点：误判时用户没有纠正机会，且系统行为不够可解释。
3. 单入口 + 自动分流 + 用户确认
   - 优点：降低用户理解成本，同时保留可纠正性。
   - 缺点：比完全自动多一步确认，但这一步能显著降低误路由风险。

### 本期选择

选择方案 3：单入口 + 自动分流 + 用户确认。

原因：它把平台能力组织为用户可理解的单一创作入口，同时在进入后续昂贵或耗时流程前给用户确认机会，适合 MS1 阶段先固化主干体验和信息结构。

## 基本概念与信息结构

### 输入资产（InputAsset）

表示用户提供的输入资产。

- `type`: `text | image | image_with_text | model`
- `content`: 文本、图片文件或模型文件
- `metadata`: 文件名、格式、尺寸、大小等基础信息

### 创作意图（CreationIntent）

表示系统根据输入推断出的创作意图。

- `route`: `concept_image | image_to_3d | model_audit`
- `confidence`: 系统识别置信度
- `userConfirmed`: 用户是否确认该流程

### 创作会话（CreationSession）

表示一次从输入到模型、审计、切片、打印的创作会话。

## 原型 / 演示

创作页包含：

- 顶部输入区：
  - 文本输入框
  - 图片上传
  - 模型上传
- 输入识别结果：
  - “已识别为：图片生成 3D”
  - “参考说明：保留圆角、适合桌面摆件”
- 主操作按钮：
  - `继续生成`
  - `修改输入`

## 验收标准

### 例子 1：纯文本输入

- 现状：用户输入“一个适合 3D 打印的龙形手机支架”，系统不知道下一步该生成图片还是模型。
- 提议后的行为：系统识别为纯文本，进入概念图生成。
- 验收：页面显示“已识别为：文本概念生成”，点击继续后生成概念图候选。

### 例子 2：图片输入

- 现状：用户上传一张玩具车图片，仍需选择生成模式。
- 提议后的行为：系统识别为图片，进入图生 3D。
- 验收：页面显示“已识别为：图片生成 3D”，点击继续后调用图生 3D 流程。

### 例子 3：非法情况

- 现状：用户上传 `.zip` 或无法解析的文件时，系统可能没有明确的下一步。
- 提议后的行为：系统不得进入生成流程。
- 验收：页面提示“当前文件类型不支持，请上传图片或 GLB/STL/OBJ 模型”。
