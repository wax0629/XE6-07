# Proposal：牛小七 × 灵矽 AI 硬件的可打印外壳适配 POC

> 状态：产品设计草案，仅供 PR 评审，不合并。达成共识后将设计基线回填至对应 Issue，再拆分实现任务。

## 动机 / 用户故事

团队希望把牛小七 IP 形象制作成一款可 3D 打印的 AI 陪伴摆件，并在外壳中容纳灵矽 AI 硬件。现有“先生成完整摆件，再人工用 CAD 挖空、设计固定件并反复打印”的做法依赖建模经验，外观模型与硬件尺寸也难以持续同步。

共同需求是：在不要求用户掌握 CAD 的前提下，将一个 IP 外观模型与一份确定的硬件规格组合为可验证、可装配、可打印的外壳方案。

## 目标用户

- 负责牛小七 IP 产品化、希望快速验证 AI 陪伴摆件的团队成员。
- 后续拥有自有 IP 和已定义硬件套件、希望定制 AI 伴侣外壳的创作者或品牌方。

## 现有做法及不足

当前 3D 生成服务能够生成或导入牛小七的外观网格，可打印拆件工具也能帮助按尺寸切分模型并添加通用连接件。但这些能力无法保证某一块具体 AI 硬件能放入模型、被稳定固定、拥有可访问的充电和声学开孔，并在修改后仍然满足打印要求。

手工建模可以完成上述工作，但需要在每次修改外观或硬件版本后重新处理内部空间、固定方式和可打印性，难以沉淀为可复用流程。

## 本期范围

本期以“牛小七 IP + 灵矽 AI 硬件 V1 + 一个经团队确认的打印配置”为唯一验收样板，确定下列行为：

- 接收或生成牛小七的外观模型，并创建独立的几何版本。
- 选择灵矽 AI 硬件 V1 后，读取其经硬件方确认的外包络、固定点、不可侵入区域、必须外露的功能面和维护要求。
- 基于完整外观模型生成内部硬件仓；内部空腔、固定件和开孔由参数化几何操作生成，而不是依赖 3D 生成模型在生成阶段猜测内部结构。
- 默认输出前壳、后壳、内部硬件托架和必要的维护盖；前后壳通过定位结构与可拆固定方式组合，硬件由独立托架固定。
- 在导出前执行网格合法性、最小壁厚、硬件干涉、安装入口、接口可达性与目标打印配置相关的检查。
- 当当前尺寸或安装位不可制造时，返回可理解的阻断原因和候选替代方案，例如调整整体尺寸、改为背部仓或底座仓，而不是静默导出不可用文件。
- 输出各零件的打印文件、装配关系与硬件兼容版本；任何几何变化创建新的 `AssetRevision` 并触发重新检查。

本期明确不做：

- 不承诺任意 IP、任意姿势、任意第三方硬件均可自动适配。
- 不让大模型自行确定硬件精确尺寸、孔位、公差、壁厚或电气安全参数。
- 不覆盖硬件电路设计、供电安全、认证、散热认证、声学效果或量产模具设计。
- 不做完整角色关节化、任意模型语义拆解或自动生成可动手办。
- 不在本提案中确定灵矽硬件 V1 的具体尺寸、紧固件规格、打印机型号、材料或商业定价；这些由后续硬件档案和验证记录确定。
- 不在本期开放给外部用户；通用定制服务只记录为后续方向。

## 关键决策与依据

### 备选方案

1. **在 3D 生成阶段直接要求模型留出内部空间**
   - 优点：一次生成即可获得外观与空腔。
   - 缺点：外观生成模型对内部尺寸、壁厚、接口朝向和可维护性缺乏可验证约束；硬件版本变化时难以复用。

2. **先生成完整外观模型，再由人工 CAD 改造**
   - 优点：设计自由度高，适合一次性的复杂定制。
   - 缺点：需要专业建模操作，无法稳定复用到其他 IP 与硬件组合。

3. **先生成完整外观模型，再由硬件档案驱动的参数化几何操作生成内部结构**
   - 优点：外观生成与硬件适配解耦；硬件版本和外观版本均可追溯；能够在生成后做确定性校验。
   - 缺点：首期必须定义硬件档案、外壳模板和检查规则，不能依赖任意网格一次成功。

### 选择与理由

选择方案 3。

本 POC 的核心不是证明“AI 能生成一个看起来有空腔的摆件”，而是验证“指定 IP 外观与指定硬件能稳定形成可打印、可装和可维护的实物”。外观模型负责视觉表达；硬件档案是内部尺寸的唯一事实来源；大模型只能提出安装区域或外观调整建议，实际布尔挖空、加固和检查必须由确定性几何流程完成。

### 外壳装配方式

1. **完整主体加小盖板**：外观接缝少，但大型主板、电池或扬声器可能无法通过小开口装入，内部固定与维修困难。
2. **主体切成多个装饰性小件**：打印方向更灵活，但接缝增多，装配和外观一致性风险更高。
3. **前后壳 + 独立托架 + 按需小维护盖**：可先完成硬件安装和通电测试，再合壳；后壳可作为较大的装配开口；高频维护件不必拆整个主体。

选择方案 3 作为 POC 默认结构。接缝应优先隐藏在背部、头身交界、服饰结构或背包式造型中；主体不能仅依赖磁铁承力，定位结构承担对齐和剪切力，可拆紧固结构承担锁紧。

## 基本概念与信息结构

- **角色外观模型**：牛小七的原始、规范化和外壳改造后的几何版本；任何改变均创建新的 `AssetRevision`。
- **硬件档案**：灵矽 AI 硬件某一版本的受控描述，至少包含外包络、固定要求、不可侵入区域、外露功能面、线缆/维护要求和适用版本。它不是由大模型自由生成的提示词。
- **外壳方案**：将一个角色外观版本与一个硬件档案、目标尺寸和打印配置绑定的候选方案；记录建议安装位、壳体分件、固定方式、检查结论和失败原因。
- **制造检查**：针对外壳方案执行的确定性检查。几何改动后，先前检查、切片和打印清单均失效，必须重新生成。

流程如下：

```text
牛小七外观模型
→ 尺寸与网格规范化
→ 选择灵矽硬件 V1 档案
→ 提出并确认安装位
→ 生成硬件仓、托架、接口孔与前后壳
→ 制造检查
→ 用户确认
→ 导出零件和装配说明
```

## 原型 / Demo

本 PR 先评审文字方案，不提交实现代码。文字定稿后，补充一个基于真实工程的交互原型，至少展示以下连续步骤：

1. 选择牛小七外观版本与灵矽硬件版本；
2. 查看 AI 建议的安装位及其理由，并允许选择候选方案；
3. 预览前后壳、托架、开孔和硬件包络；
4. 查看通过、警告或阻断的制造检查结果；
5. 在通过且用户确认后导出零件与装配说明。

## 验收标准

### 例子 1：硬件可以装入且可维护

- 现状：完整摆件模型无法证明灵矽硬件是否能装入、固定或拆出。
- 提议后的行为：用户选择牛小七外观版本和灵矽硬件 V1 后，系统生成前后壳、托架和所需开孔的候选方案。
- 验收：团队使用该方案的实物打印件完成硬件装入、固定、通电和拆出；充电口、声音/传感器开口等在硬件档案中标记为必须外露的功能面可访问。

### 例子 2：空间不足时不导出不可制造方案

- 现状：硬件仓可能挖穿外观、造成薄壁，或没有足够的安装入口。
- 提议后的行为：系统检查候选安装位；不满足要求时阻断该方案，并给出调整尺寸、背部仓、底座仓或人工重新选择安装位等候选动作。
- 验收：对至少一个故意缩小尺寸或放入错误安装位的样例，系统不将其标记为可导出，并提供可理解的失败原因。

### 例子 3：几何修改后的检查结果不会被复用

- 现状：生成硬件仓、开孔或分件后，旧的模型检查结果可能仍被错误使用。
- 提议后的行为：每次外壳几何变化创建新版本，并使旧检查、切片和打印清单失效。
- 验收：对牛小七外观做一次硬件仓或开孔修改后，系统要求重新完成制造检查，未通过检查的版本不能进入切片或打印确认。

### 例子 4：硬件版本变化可追溯

- 现状：硬件尺寸或接口调整后，旧外壳与新硬件的兼容性不明确。
- 提议后的行为：每个外壳方案记录所依赖的灵矽硬件档案版本。
- 验收：将硬件档案从 V1 切换为另一个版本后，系统不将原外壳自动宣称为兼容，必须重新生成或重新验证方案。
