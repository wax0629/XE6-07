# 提案：人脸细节修复

## 动机 / 用户故事

人物类图片在增强或重建后，容易出现脸部模糊、五官不清或身份特征丢失。即使整体结果可用，人脸区域的明显缺陷也会显著降低成品质量和可识别度。

共同需求是：只在输入中检测到人脸时，对脸部区域执行受控修复，同时尽量保持整体风格和非人脸区域不变。

## 目标用户

- 使用人物图片生成或重建 3D 内容的普通用户
- 需要消费增强后人物图像的后续重建模块

## 现有做法及不足

当前增强或重建流程对全图统一处理，人物脸部可能因分辨率、姿态或生成误差失去细节。对所有图片无条件启用人脸修复又会误处理非人脸内容，并可能破坏整体风格。

## 本期范围

本期做：

- 检测输入或中间结果中的人脸区域。
- 仅对检测到的脸部区域执行修复。
- 增强五官细节和人物可识别度。
- 非人脸场景自动跳过人脸修复。
- 保留修复是否触发和处理区域的信息，供后续流程判断。

本期明确不做：

- 不对非人脸区域执行同类修复。
- 待讨论：是否支持多人脸、遮挡脸和极端侧脸。
- 待讨论：是否允许用户调整修复强度或手动选择人脸。
- 待讨论：身份一致性和风格保持的量化门槛。

## 关键决策与依据

### 备选方案

待讨论：需要补充“全图增强”“检测后局部修复”“由用户手动指定区域”等方案的质量、性能和误触发对比。

### 本期选择

现有范围确定采用“检测到人脸后，仅修复脸部区域；非人脸自动跳过”。

该选择减少了对无关区域的修改，但触发阈值、修复强度和身份保持标准仍需团队确认。

## 基本概念与信息结构

### 人脸检测结果

- 是否检测到人脸。
- 检测到的脸部区域。
- 待讨论：置信度、多人脸列表和姿态信息。

### 修复结果

- 修复后的图像。
- 是否执行修复。
- 实际修改的脸部区域。
- 待讨论：修复模型版本和质量评分。

## 原型 / 演示

待讨论：需要展示修复前后对比、人脸检测中、未检测到人脸、修复失败和自动跳过状态。

## 验收标准

### 例子 1：检测到清晰人脸

- 现状：人物图像中的脸部模糊，五官细节不足。
- 提议后的行为：系统检测人脸，仅对脸部区域执行修复和细节增强。
- 验收：输出标记修复已触发并记录处理区域；脸部细节达到约定质量标准，非人脸区域没有明显变化。具体评测集和阈值待讨论。

### 例子 2：非人脸场景

- 现状：无条件执行人脸修复可能误处理玩具、纹理或背景图案。
- 提议后的行为：系统未检测到人脸时跳过修复。
- 验收：不调用人脸修复处理，不伪造人脸区域，输出明确标记为“已跳过”，原图可继续进入后续流程。

### 例子 3：低置信度或受遮挡人脸

- 现状：低置信度检测结果可能触发错误修复并改变身份特征。
- 提议后的行为：系统依据待确认阈值决定跳过、提示或继续修复。
- 验收：低于阈值时不静默修改图像；最终阈值和用户确认规则待讨论。

### 例子 4：修复执行失败

- 现状：修复失败可能让后续流程误以为已经得到增强结果。
- 提议后的行为：系统保留原始输入并返回明确失败状态。
- 验收：失败时不覆盖原图，后续模块可以区分“未触发”“修复成功”和“修复失败”。
