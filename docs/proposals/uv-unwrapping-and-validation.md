# 提案：UV 展开与质量检查

## 动机 / 用户故事

模型需要通过 UV 把二维贴图稳定映射到三维表面。缺少可用 UV 时，纹理会错位、拉伸或无法进入后续贴图整理流程，直接影响模型显示和交付质量。

共同需求是：为模型生成可用 UV，并在交给贴图模块前检查重叠、拉伸和破碎等基础质量问题。

## 目标用户

- 需要生成带纹理 3D 模型的普通用户
- 消费 UV 结果的贴图整理和模型交付模块

## 现有做法及不足

没有统一 UV 展开与检查时，贴图模块可能收到无 UV、严重重叠或异常拉伸的模型，只能在更晚阶段发现问题，增加返工成本。

## 本期范围

本期做：

- 对模型执行 UV 展开。
- 检查 UV 重叠。
- 检查 UV 拉伸和异常破碎。
- 确认 UV 是否满足贴图整理模块的基础输入要求。
- 输出检查结果，区分通过和需要返工的模型。

本期明确不做：

- 待讨论：是否生成或编辑实际贴图。
- 待讨论：是否支持用户手工调整 UV 岛。
- 待讨论：如何处理模型已有 UV，是保留、覆盖还是按质量选择。
- 待讨论：UDIM、多材质和复杂 UV 分区是否属于本期。

## 关键决策与依据

### 备选方案

待讨论：需要比较“始终重新展开”“优先复用已有 UV”“只检查不展开”等方案，并明确不同模型类型的选择规则。

### 本期选择

现有范围确定同时提供 UV 展开和基础质量检查。

重叠、拉伸、破碎的量化阈值，以及已有 UV 的处理策略仍需团队确认。

## 基本概念与信息结构

### UV 展开结果

- 模型表面到二维 UV 空间的映射。
- 待讨论：UV 岛、边距、分辨率和坐标约束。

### UV 检查结果

- 是否存在重叠。
- 是否存在异常拉伸。
- 是否存在异常破碎。
- 是否可供贴图整理模块使用。
- 待讨论：问题位置、严重度和量化指标。

## 原型 / 演示

本期主要是模型处理能力。若提供界面，至少需要展示处理中、检查通过、检查失败和问题摘要；是否展示 UV 布局预览待讨论。

## 验收标准

### 例子 1：无 UV 的有效模型

- 现状：模型没有 UV，贴图模块无法映射纹理。
- 提议后的行为：系统完成 UV 展开并运行基础检查。
- 验收：输出包含可读取 UV 的模型和检查结果；贴图整理模块可以直接加载该 UV。岛间边距和覆盖率阈值待讨论。

### 例子 2：存在明显 UV 重叠

- 现状：重叠区域会让不同表面错误共享同一纹理位置。
- 提议后的行为：系统检测重叠并把结果标记为不通过或需要返工。
- 验收：检查结果能定位重叠区域并给出严重度；允许的有意重叠规则和阈值待讨论。

### 例子 3：异常拉伸或破碎

- 现状：过度拉伸或碎片化 UV 会造成纹理失真和编辑困难。
- 提议后的行为：系统检测异常拉伸和破碎。
- 验收：超过约定阈值时结果不通过，并提供可定位的问题信息；具体指标和阈值待讨论。

### 例子 4：交给贴图整理模块

- 现状：UV 检查通过不一定意味着下游能够读取实际结果。
- 提议后的行为：通过检查的模型作为贴图整理模块的输入。
- 验收：下游能够读取 UV 坐标并正确映射测试纹理，不需要重新展开或修复数据格式。

### 例子 5：无效网格或已有 UV

- 现状：无效网格可能无法展开；已有 UV 可能被不必要覆盖。
- 提议后的行为：系统在处理前识别输入状态，并按待确认规则拒绝、保留或重新展开。
- 验收：不静默覆盖已有 UV，也不对失败结果标记通过；最终分支规则待讨论。
