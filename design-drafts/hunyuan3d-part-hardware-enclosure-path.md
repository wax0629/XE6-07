# 技术实现路径构想：Hunyuan3D-Part 驱动的硬件仓确定性改模链路

> 状态：技术设计草案，仅用于逐行评审，不进入合并。  
> 关联产品方向：牛小七 IP 模型内置灵矽 AI 硬件的 PoC。  
> 本文不改变产品范围，也不提交生产实现；目标是验证一条可演进、可回退的技术路径。

## 1. 背景与结论

团队已经部署 Hunyuan3D，可生成完整三维模型。下一步需要在不明显破坏角色外观的前提下，为主板、电池、扬声器、走线、声学孔和装配结构生成内部空间，并输出可打印、可组装的新模型。

建议采用“AI 理解与候选定位 + 参数化规划 + 确定性几何执行”的分层链路：

1. 现有 Hunyuan3D 继续负责完整模型生成，不改变其职责。
2. Hunyuan3D-Part 的 P3-SAM 作为候选零件分割器，输出面级分区与预览。
3. 视觉语言模型、规则和用户确认共同完成语义命名与可操作区域选择。
4. 几何规划器把硬件尺寸、间隙、壁厚、开孔和装配方式转换为可审查的参数化配方。
5. MeshLib、Manifold 等确定性几何引擎执行布尔运算、拆壳、卡扣/螺柱/定位结构生成及网格修复。
6. 装配检查和可打印性检查通过后，才生成新的模型版本。

P3-SAM 可以帮助回答“模型表面有哪些稳定的局部区域”，但不能单独回答“这是后脑、这里应该开盖、内部能否容纳硬件”，更不能替代精确几何计算。因此本路径不以“Part 模型直接生成最终可打印模型”为目标。

## 2. 范围与非目标

### 本阶段范围

- 验证牛小七模型能否获得稳定、可回映到原网格的面级分区。
- 验证点提示能否选中后脑、背部等预期开仓候选区域。
- 定义从模型版本、分区结果、几何配方到新模型版本的最小闭环。
- 明确 AI 决策、用户确认和确定性几何引擎之间的责任边界。
- 记录运行耗时、显存峰值、失败类型和人工修正次数。

### 非目标

- 不在本 PR 中确定数据库表、最终 API 字段或供应商绑定。
- 不承诺任意模型均可全自动改造。
- 不让大模型直接输出或修改三角面坐标。
- 不在首轮验证中实现卡扣、完整托架或量产级声学设计。
- 不将 P3-SAM 与现有 Hunyuan3D 推理服务加载到同一进程。

## 3. 总体链路

```text
AssetRevision（原始模型版本）
  -> 网格规范化与哈希绑定
  -> Part Segmentation Adapter（P3-SAM 候选）
  -> 面级分区 + AABB + 彩色预览 Artifact
  -> 语义命名 / 规则筛选 / 用户确认
  -> Geometry Planner（硬件包络与装配约束）
  -> Geometry Recipe（可审查参数）
  -> Deterministic Mesh Adapter（MeshLib / Manifold）
  -> 装配检查 + 可打印性检查
  -> 新 AssetRevision + 零件 Artifact + WorkflowEvent
```

任何一步失败都不得覆盖原模型；所有派生结果必须绑定输入模型版本、内容哈希、面顺序以及模型/引擎版本。

## 4. 模块职责

### 4.1 现有 Hunyuan3D 生成服务

- 继续输出完整 GLB/网格及其资产版本。
- 不负责零件语义、内部空间或连接结构。
- 延续独立推理服务 + Adapter 调用方式，避免产品后端直接耦合模型运行环境。

### 4.2 Part Segmentation Adapter

PoC 候选使用 Hunyuan3D-Part 中的 P3-SAM：

- 输入规范化后的模型和可选的表面点提示。
- 自动模式输出 class-agnostic 的零件实例，而不是“头部”“后脑”等可靠语义标签。
- 保存每个三角面的 `face_id -> part_id` 映射、分区包围盒、置信信息和着色预览。
- 输出必须包含来源版本、输入哈希、模型版本和运行参数。
- 若修复、重拓扑、减面改变了面顺序，旧分区立即失效，必须重跑或重新投影。

首轮只验证 P3-SAM。X-Part 偏向从不完整零件恢复完整几何，不是本需求的必要环节。

### 4.3 Semantic Grounding 与确认层

该层把无语义分区转成“头部、后脑、躯干、底部”等可操作候选：

- 视觉语言模型基于多视图渲染提出语义标签和候选区域。
- 几何规则使用高度、法向、曲率、可见性、厚度和对称性过滤不合理候选。
- 用户在彩色预览中点击或确认最终操作区域。
- 输出“建议及证据”，不直接执行几何修改。

PoC 默认保留一次人工确认。只有在固定 IP、固定硬件套件和足够回归样本下，才评估跳过确认。

### 4.4 Geometry Planner

规划器接收硬件包络及约束，生成可审查的 `Geometry Recipe`：

- 主板、电池和扬声器的包络尺寸与装配间隙。
- 目标区域、开仓方向和拆件平面。
- 最小壁厚、圆角、避让区和重心约束。
- USB、麦克风、扬声器、电源开关所需通道与开孔。
- 盖板、前后壳或底盖方案，以及螺柱、定位销、卡扣等接口参数。
- 打印方向、支撑限制和材料/工艺公差。

大模型可以根据语义结果、硬件规格和规则库填写这些参数，但每个参数都必须经过范围校验；越界、冲突或缺失时转为人工确认，不能直接传给几何引擎。

### 4.5 Deterministic Mesh Adapter

- 将参数化硬件包络转换为实体并执行布尔差、布尔并、切割和拆壳。
- 生成盖板、托架、螺柱、定位结构及必要开孔。
- 修复自交、非流形边、孔洞和退化三角形。
- 输出主体、盖板/壳体、托架等独立零件以及装配变换。
- 对上层只暴露统一能力，PoC 可先接 MeshLib；替换引擎时不改变业务链路。

几何引擎负责“在精确坐标上怎么切”，不负责判断“角色哪里是后脑、哪里应该动”。

### 4.6 装配与可打印性检查

至少检查：

- 零件间干涉和硬件装入路径。
- 剩余壁厚、最小特征、悬垂和封闭体。
- 声孔、麦克风孔、USB 口是否贯通且未被托架遮挡。
- 盖板/壳体配合间隙和紧固结构是否完整。
- 输出零件组合后是否恢复预期外形。

检查不通过时记录失败原因，返回规划层调整参数；不得把无法验证的结果标记为完成。

## 5. 概念数据与版本约束

本构想只定义必须存在的概念，不冻结存储结构：

- `Source Revision`：不可变的输入模型版本与内容哈希。
- `Part Mask Artifact`：面级分区、AABB、预览和提示点。
- `Semantic Decision`：候选标签、证据、确认人或自动规则版本。
- `Hardware Envelope`：硬件实体包络、接口位置和安全间隙。
- `Geometry Recipe`：经校验的切割、开孔和连接结构参数。
- `Derived Artifacts`：主体、盖板/壳体、托架及装配关系。
- `Validation Report`：装配与可打印性检查结果。

现有简单后处理操作不能预设能够表达“主体 + 后盖 + 托架”的多输出关系。如何映射到资产版本和零件集合，应在技术验证后单独评审。

## 6. 最小端到端时序

1. 用户选择牛小七的某个 `AssetRevision` 和灵矽硬件套件。
2. 后端创建持久化任务，规范化网格并记录输入哈希。
3. P3-SAM Worker 自动分区，保存面级结果和着色预览。
4. 用户点击后脑候选点；Adapter 生成或修正目标分区。
5. 规划器基于硬件包络生成后置仓、开孔和装配参数预览。
6. 用户确认配方后，确定性几何引擎生成派生零件。
7. 检查器验证干涉、壁厚、贯通孔、闭合性和组合完整性。
8. 通过后创建新模型版本并发布工作流事件；失败则保留原版本和诊断报告。
9. 客户端通过同一任务 ID 查询分区、配方、派生模型和检查状态。

## 7. 失败与回退

- 自动分区不稳定：切换为点提示，仍失败则人工框选/涂抹区域。
- 语义标签不可靠：只展示候选，不执行改模，要求用户确认。
- 硬件放不下：返回尺寸冲突、最薄壁位置和建议缩放，不擅自缩放 IP 模型。
- 布尔运算失败：尝试规范化/修复后重算；仍失败则保留配方和诊断件供人工 CAD 处理。
- 开孔破坏外观：在允许区域内搜索替代方向，无法满足时终止。
- 检查失败：派生版本保持未完成，不进入打印导出。

## 8. 对当前仓库的影响构想

当前后端已有资产版本、Artifact、任务和工作流事件等基础概念。建议按现有 Adapter/Worker 边界扩展，而不是在 API 进程内加载 P3-SAM 或 MeshLib：

- 新增 Part Segmentation Adapter 与独立 Worker。
- 新增 Geometry Planner 与 Deterministic Mesh Adapter。
- 复用资产版本和 Artifact 存储分区预览、几何配方、派生零件及检查报告。
- 复用任务状态和工作流事件形成可追踪闭环。
- 在实现前先用 Mock Adapter 跑通持久化任务到新版本回读，再分别替换真实分割与真实几何引擎。

这些是模块边界建议，不代表本 PR 批准新增接口、表或生产依赖。

## 9. 分阶段技术验证

### Spike A：P3-SAM 能力与成本

- 在独立 Python 3.10 / PyTorch / CUDA 环境部署 P3-SAM。
- 对牛小七 GLB 运行自动分区，保存 `face_ids`、AABB 和彩色 GLB。
- 在后脑区域执行一次点提示分区。
- 证明结果能按原面顺序回映到同一来源版本。
- 记录模型面数、运行耗时、显存峰值、失败类型和人工修正次数。
- 本阶段不做任何布尔改模。

验收：至少一次成功输出可审查预览；失败时原模型不变，且有可定位的错误记录。

### Spike B：后端 Mock 闭环

跑通：持久化任务 -> Mock Part Adapter -> 分区 Artifact -> Mock Geometry Recipe -> Mock Mesh Adapter -> 新 AssetRevision -> WorkflowEvent -> 同任务 ID 回读。

验收：进程重启后任务和派生资产仍可查询，失败任务不产生“已完成”版本。

### Spike C：确定性几何最小样件

- 只实现一个矩形硬件包络的内部布尔差。
- 生成一个可拆底盖或后盖，以及最小定位结构。
- 检查封闭性、壁厚、硬件干涉和零件组合完整性。
- 打印缩小样件验证装入路径与公差。

验收：源文件、主体、盖板和检查报告均可追踪；实际硬件能够装入并完成基本拆装。

### Spike D：AI 参数建议

- 使用语义结果、硬件规格和规则库生成 Geometry Recipe 候选。
- 对所有参数做类型、范围、碰撞和制造约束校验。
- 比较 AI 建议与人工基准的区域命中率、参数修改量和成功率。

验收：任何未通过校验的参数均不能触发几何执行。

## 10. 部署与许可风险

- P3-SAM 是独立下游模型，不是现有 Hunyuan3D 生成服务的开关，需要独立环境、权重、GPU 测试和服务封装。
- 官方主要提供脚本/演示入口，不应直接视为稳定生产 API；团队需封装版本化 Adapter、超时、错误码和资源隔离。
- 官方环境示例不能替代本机显存测试，模型权重文件大小也不能代表运行显存。
- P3-SAM 依赖 Sonata。Sonata 代码许可与预训练权重许可不同，其中权重的非商业限制可能阻断商业产品使用。
- Hunyuan3D-Part 自身采用定制许可，包含地域、托管服务及规模等条款。进入商业研发或对外服务前，必须完成法务确认，或更换可商用编码器/分割模型。

许可未澄清前，P3-SAM 仅用于许可允许范围内的技术评估，不进入生产链路。

## 11. 建议任务拆分

1. 分割验证：部署 P3-SAM、固定输入规范、产出可回映结果与资源报告。
2. 几何验证：选型 MeshLib/Manifold，完成布尔差、拆盖和最小检查。
3. 后端闭环：用 Mock Adapter 接入任务、Artifact、版本与事件。
4. 交互验证：实现分区预览、点击修正和 Geometry Recipe 确认。
5. AI 规划验证：建立硬件模板和规则库，再接入大模型参数建议。
6. 许可评审：确认 P3-SAM、Sonata 与 Hunyuan3D-Part 的商业使用边界。

每项实现应由独立 Issue 和范围受限的代码 PR 承接；本技术构想 PR 只收集评审意见，不作为代码合并入口。

## 12. 待评审问题

- 首个可拆结构优先选择后盖还是底盖，是否允许在背面留下可见分件线？
- 首版是否只支持固定牛小七模型与固定硬件套件，暂不承诺任意模型？
- P3-SAM 许可不能满足商业化时，替代分割模型的最低精度与许可要求是什么？
- 多输出零件应如何映射到现有资产版本与零件集合？
- 可打印性检查采用现有能力扩展，还是单独建立装配检查报告？
- Geometry Recipe 在什么阶段允许从人工确认升级为自动执行？
